# PayChauki – Sprint Plan

## Project Overview

**Project:** PayChauki  
**Development Approach:** Scrum-based Agile  
**Project Type:** Academic Software Engineering Prototype  
**Total Story Points:** 46

PayChauki is a prototype for transaction monitoring and rule-based fraud detection using simulated transaction data.

## Sprint 1 – Foundation and Basic System

**Goal:** Establish the core system and customer access.

**Story Points:** 12

### User Stories
- [3SP] US-01 – User Registration
- [3SP] US-02 – Secure Login
- [3SP] US-03 – Transaction History
- [3SP] US-04 – Record Transaction

### Main Features
- User registration
- Secure login and logout
- User roles
- Transaction recording
- Transaction history
- Basic user interface

### Sprint Completion Criteria
- Functional requirements are implemented.
- Acceptance criteria are satisfied.
- Features are tested.
- Critical defects are resolved or documented.
- Code is committed to GitHub.
- Relevant documentation is updated.

---

## Sprint 2 – Fraud Detection

**Goal:** Implement the core fraud monitoring workflow.

**Story Points:** 21

### User Stories
- [8SP] US-05 – Fraud Detection
- [5SP] US-06 – Fraud Alert
- [8SP] US-07 – Block High-Risk Transaction

### Main Features
- Predefined fraud detection rules
- Risk level assignment
- Suspicious transaction flagging
- Fraud alerts
- High-risk transaction blocking

### Sprint Completion Criteria
- Fraud rules are implemented and tested.
- Low, Medium, and High risk levels are supported.
- Suspicious transactions are flagged.
- Alerts are generated for suspicious activity.
- High-risk transactions are blocked according to configured rules.
- Changes are committed to GitHub and documented.

---

## Sprint 3 – Investigation and Administration

**Goal:** Complete investigation and administrative functionality and prepare for testing and deployment.

**Story Points:** 13

### User Stories
- [3SP] US-08 – Report Fraud
- [5SP] US-09 – Fraud Case Review
- [5SP] US-10 – User and Rule Management

### Main Features
- Fraud reporting
- Fraud analyst dashboard
- Fraud case management
- User management
- Fraud rule management
- Testing preparation
- Deployment preparation

### Sprint Completion Criteria
- Fraud reports can be submitted.
- Analysts can review flagged and reported transactions.
- Fraud case statuses can be updated.
- Administrators can manage users and basic fraud rules.
- Required testing is completed or documented.
- Prototype deployment and demonstration are prepared.
