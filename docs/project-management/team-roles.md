# PayChauki – Team Roles

## Project Team

PayChauki is a four-person Scrum-based Agile software engineering project. The team members and their assigned roles are:

| Team Member | Role |
|---|---|
| **Nirjala Ghimire** | Product Owner |
| **Chhumi Lama** | System Architect |
| **Saibya Timilsina** | Scrum Master |
| **Sandesh Shrestha** | QA & DevOps Lead / Developer |

## 1. Nirjala Ghimire – Product Owner

**Primary Responsibility:** Manage product priorities and ensure that the team delivers the required PayChauki functionality.

**Responsibilities:**
- Maintain and prioritize the Product Backlog.
- Clarify user stories and acceptance criteria.
- Review completed work.
- Help determine sprint priorities.
- Confirm that implemented features meet project requirements.
- Represent the product requirements and stakeholder needs.

## 2. Chhumi Lama – System Architect

**Primary Responsibility:** Design and guide the overall technical architecture of the PayChauki system.

**Responsibilities:**
- Design the overall system architecture.
- Define the structure and interaction of major system components.
- Support database and system design decisions.
- Ensure that the architecture supports authentication, transactions, fraud detection, alerts, and case management.
- Guide developers on technical implementation.
- Review technical decisions and maintain architectural documentation.

## 3. Saibya Timilsina – Scrum Master

**Primary Responsibility:** Facilitate the Scrum process and support effective team collaboration.

**Responsibilities:**
- Facilitate sprint planning and Scrum activities.
- Track sprint progress.
- Help identify and remove blockers.
- Encourage communication and collaboration.
- Ensure that the team follows the agreed Scrum workflow.
- Coordinate with the Product Owner and team members.
- Help maintain Trello sprint boards and project progress.

## 4. Sandesh Shrestha – QA & DevOps Lead / Developer

**Primary Responsibility:** Lead quality assurance, DevOps activities, and software development tasks.

**Responsibilities:**
- Plan and perform functional testing.
- Support security, integration, system, UI, and performance testing.
- Record and track defects.
- Verify that implemented features meet acceptance criteria.
- Support CI/CD and deployment activities.
- Maintain development and deployment workflows.
- Contribute to application development and bug fixing.
- Support GitHub repository management and release preparation.

## Shared Team Responsibilities

All team members are expected to contribute to:

- Requirements analysis
- System design
- Development
- Code review
- GitHub collaboration
- Testing
- Bug fixing
- Documentation
- Sprint reviews
- Prototype demonstration
- Deployment preparation

## GitHub Workflow

The team should:

1. Create a branch for assigned work where appropriate.
2. Commit changes regularly with clear commit messages.
3. Review changes before merging.
4. Keep the main branch stable.
5. Update documentation when relevant.
6. Link completed work to the appropriate Trello card.

## Definition of Done

A backlog item is complete when:

- Functional requirements have been implemented.
- Acceptance criteria have been satisfied.
- Relevant testing has been completed.
- Critical defects have been resolved or documented.
- Code has been committed to the repository.
- Relevant documentation has been updated.
- The work has been reviewed according to the team's GitHub workflow.
